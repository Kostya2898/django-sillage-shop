# API кошика для фронтенду

Документ описує ендпоінти, якими користується JavaScript. Формат відповідей
фіксований: якщо він змінюється — змінюється і цей файл, інакше фронтенд
дізнається про зміну з поламаної сторінки.

Реалізація: `cart/views.py`, формат — `cart/services.py`.

---

## Принцип: прогресивне покращення

Кожен ендпоінт працює у **двох режимах**, за одним і тим самим URL:

| Запит | Відповідь |
|---|---|
| Звичайний POST з `<form>` | дія → повідомлення → `302 Redirect` |
| POST із заголовком (нижче) | дія → `200` з JSON |

Це не два різні API. Валідація, ліміти й побічні ефекти однакові — різниця
лише у форматі відповіді. **Без JavaScript магазин лишається повністю
робочим**, включно з додаванням у кошик і оформленням замовлення.

### Як попросити JSON

Достатньо **одного** з двох заголовків:

```
X-Requested-With: XMLHttpRequest
```
```
Accept: application/json
```

Перший — класика `fetch`/jQuery, другий — те, чим користуються сучасні
клієнти й `curl`. Обидва підтримані навмисно: різні клієнти шлють різне.

## CSRF

Ендпоінти лишаються під захистом CSRF — вимикати його для «зручності
фронтенду» не можна, це прибрало б захист і з форм.

Токен лежить у cookie `csrftoken` і має їхати в заголовку `X-CSRFToken`:

```js
function csrfToken() {
    return document.cookie
        .split('; ')
        .find(row => row.startsWith('csrftoken='))
        ?.split('=')[1] ?? '';
}

async function addToCart(productId, quantity = 1) {
    const response = await fetch(`/cart/add/${productId}/`, {
        method: 'POST',
        headers: {
            'X-Requested-With': 'XMLHttpRequest',
            'X-CSRFToken': csrfToken(),
            'Content-Type': 'application/x-www-form-urlencoded',
        },
        body: new URLSearchParams({quantity}),
    });
    return response.json();
}
```

Якщо cookie немає (користувач ще не отримав жодної сторінки), візьміть токен
із прихованого поля будь-якої форми: `document.querySelector('[name=csrfmiddlewaretoken]').value`.

## Ендпоінти

Усі — тільки `POST`. `GET` повертає `405`.

| URL | Тіло | Що робить |
|---|---|---|
| `/cart/add/<id>/` | `quantity` (за замовчуванням 1) | додає до наявної кількості |
| `/cart/update/<id>/` | `quantity` | **встановлює** кількість; `0` видаляє позицію |
| `/cart/remove/<id>/` | — | видаляє позицію |
| `/cart/clear/` | — | очищає кошик |

## Успішна відповідь

```json
{
  "ok": true,
  "count": 3,
  "total_display": "12 600 ₴",
  "item": {
    "id": 7,
    "slug": "kedrova-tysha",
    "name": "Кедрова тиша",
    "brand": "Nord Botanica",
    "url": "/product/kedrova-tysha/",
    "image": "/media/products/covers/2026/08/kedrova-tysha-front.webp",
    "quantity": 3,
    "price_display": "4 200 ₴",
    "total_display": "12 600 ₴"
  },
  "cart_html": "<div class=\"cart-drawer\" id=\"cart-drawer\" …>…</div>",
  "message": "Товар «Кедрова тиша» додано до кошика"
}
```

| Поле | Тип | Призначення |
|---|---|---|
| `ok` | bool | завжди `true` в успішній відповіді |
| `count` | int | одиниць у кошику — для лічильника в шапці |
| `total_display` | str | готова сума, підставляти як є |
| `item` | object \| null | позиція, якої стосувалась дія; `null` після видалення й очищення |
| `cart_html` | str | відрендерений `templates/cart/_drawer.html` |
| `message` | str | текст для тоста, українською |

### Чому `item` містить фото й назву

Щоб анімація «товар полетів у кошик» відпрацювала **без другого запиту**:
у відповіді вже є `image`, `name`, `brand` і `quantity` — достатньо, щоб
намалювати летючу мініатюру й одразу оновити drawer.

### Чому суми приходять рядком

`total_display` і `price_display` форматуються на бекенді у вигляді
`4 850 ₴` — з **нерозривними** пробілами (`U+00A0`), щоб число не
розірвалось переносом рядка. Фронтенд не займається локалізацією чисел:
інакше формат розʼїхався б між drawer-ом, сторінкою кошика і checkout-ом.

Якщо потрібне сире число для розрахунків — беріть його з DOM або додайте
окреме поле; свідомо не віддаємо обидва формати, щоб не було спокуси
рахувати суми на клієнті.

## Відмова: очікуваний бізнес-стан

```json
{
  "ok": false,
  "error": "На складі лишилось 2 од. товару «Кедрова тиша». У кошику вже 1 — можна додати ще 1."
}
```

**HTTP-статус лишається `200`.** Брак товару на складі — це нормальна
відповідь системи, а не збій: не треба ловити її в `catch`. Перевіряйте
`payload.ok`.

Тіло відмови містить **тільки** `ok` і `error` — жодних `count` чи
`cart_html`, бо кошик не змінився.

### Коли справді помилка

| Статус | Причина |
|---|---|
| `404` | товару з таким `id` не існує |
| `405` | метод не `POST` |
| `403` | не пройшов CSRF |

---

## Валідація

- кількість — ціле число від `1` до `CART_MAX_QUANTITY_PER_PRODUCT` (за
  замовчуванням `99`, налаштовується в `.env`);
- підсумок у кошику після дії не може перевищити `stock` товару —
  перевіряється саме підсумок, а не число із запиту;
- товар має бути `is_available`;
- сміття в `quantity` трактується як `1`, а не як помилка.

## Шаблонні фрагменти

Одна розмітка на всі місця, щоб вони не розʼїхались:

| Файл | Що це |
|---|---|
| `templates/cart/_drawer.html` | висувна панель; саме він приходить у `cart_html` |
| `templates/cart/_row.html` | одна позиція кошика |
| `templates/cart/_summary.html` | підсумок (кількість і сума) |

Найпростіший спосіб оновити інтерфейс — підмінити розмітку цілком:

```js
const payload = await addToCart(productId);
if (!payload.ok) return showToast(payload.error, 'error');

document.getElementById('cart-drawer').outerHTML = payload.cart_html;
document.querySelector('[data-cart-count]').textContent = payload.count;
showToast(payload.message, 'success');
```

Drawer має `data-count` на кореневому елементі — зручно, якщо потрібен лише
лічильник без парсингу.
